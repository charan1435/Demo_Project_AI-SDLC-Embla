## Dev Plan: AI-1657 — Prisma schema and initial migration for all domain entities

### Approach
- Scaffold minimal `backend/` project (package.json, tsconfig.json, `prisma` + `@prisma/client` + `typescript` deps) so Prisma CLI/client can run (AI-1659)
- Author `backend/src/db/schema.prisma` with all 9 models (Admin, Teacher, Student, Class, Subject, Enrollment, TeacherAssignment, Session, AttendanceRecord) and the `AttendanceStatus` enum, exactly per design spec §3 (AI-1658)
- Configure Prisma's schema path (`package.json` `prisma.schema` field or `--schema` flag) to point at the non-default `backend/src/db/schema.prisma` location
- Add `backend/.env` / `.env.example` with `DATABASE_URL` so `prisma migrate dev` has a target Postgres instance
- Run `npx prisma migrate dev --name init` to generate and apply the initial migration against a local Postgres database (AI-1660)
- Generate Prisma Client and verify relation types/navigability match the domain model with a small smoke-test script (AI-1661)

### Files to change
- `backend/package.json` — new, Prisma/TypeScript dependencies + schema path config
- `backend/tsconfig.json` — new, Node + TypeScript target per CLAUDE.md tech stack
- `backend/src/db/schema.prisma` — new, all 9 models + `AttendanceStatus` enum per §3
- `backend/.env.example` — new, `DATABASE_URL` placeholder
- `backend/prisma/migrations/<timestamp>_init/` — generated by `prisma migrate dev`

### Edge cases / risks
- `TeacherAssignment.classId` must stay nullable (`String?`) — required by mistake would silently break "unscoped assignment = all classes for this subject" semantics (AC #4)
- `@@unique([studentId, sessionId])` on `AttendanceRecord` and `@@unique([studentId, subjectId])` on `Enrollment` must be present exactly as specified — back non-negotiable constraint #4 (no-duplicate-attendance, DB-enforced) and the enrollment check
- `AttendanceStatus` enum must define only `PRESENT` — no `ABSENT` value, per Decision A (absence is derived at query time, never stored)
- Re-running `prisma migrate dev` on an already-migrated DB must be a no-op (no drift) — verify as part of AI-1660
- Migration must fail loudly (non-zero exit) on a schema referencing a nonexistent field/relation, rather than silently applying a broken state
